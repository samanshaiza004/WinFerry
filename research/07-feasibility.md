# Feasibility recommendation: CONDITIONAL GO

As of **2026-10-10**, authorize a bounded technical prototype, not a full consumer product commitment. The recommendation is **INFERRED** from [native ABI and distribution evidence](02-native-arm64-wine.md), [FEX source/report evidence](03-fex-hangover.md), and [graphics source inspection](04-graphics.md). A tiny Windows console test ran through Hangover/FEX in an ARM64 Linux guest; no Windows application ran through WinFerry's native macOS runtime.

## Answers to the ten decision questions

1. **Best foundation:** upstream Wine's ARM64 host and ARM64EC PE architecture, FEX's **Windows PE frontend** and ARM64 UnixLib adapter, Wine's existing macOS driver. Follow Hangover's division of labor. Use published Darwin Wine work as a narrow diagnostic patch queue while seeking upstream integration. Do not port FEX's complete Linux runtime or recreate Windows APIs. [02](02-native-arm64-wine.md), [03](03-fex-hangover.md).
2. **How close:** reported end-to-end previews and independent developer tests exist, plus inspectable loader/ABI patches and a small public FEX shim. The gap is a clean-source, signed, reproducible, correct and distributable stack. No defensible percentage or completion date can be assigned. [02](02-native-arm64-wine.md), [03](03-fex-hangover.md).
3. **What works today:** CodeWeavers reports native Mac ARM64 Wine/FEX preview execution; FEX PE/ARM64EC and Hangover are public implementations; DXMT has both ARM64EC and Darwin ARM64 build configurations. Locally, one source-built ARM64 console PE passed through Linux Wine, and the paired x64 PE passed five later clean-prefix runs through FEX, after two assertion failures in one earlier prefix. Native macOS execution remains **UNTESTED**. [01](01-landscape.md), [04](04-graphics.md), [experiment results](experiments/README.md), [Linux reference](experiments/linux-arm64-reference/README.md).
4. **Single biggest blocker:** independent authorization and redistribution of the restricted macOS cross-architecture execution environment on **unrelated stock Macs**. Split the investigation: Gate0A asks whether a provisioned development build can run the required process features; Gate0B asks whether a publisher can distribute that runtime to an ordinary unrelated user. The largest subsequent runtime correctness risk is JIT/SMC/protection/exception integration. These are separate gates. [02](02-native-arm64-wine.md), [06](06-licensing-security.md), [roadmap](09-roadmap.md).
5. **Minimum implementation to resolve uncertainty:** the Linux reference now proves a tiny Win32 console path and one x64 PE through FEX; diagnose the prefix-local assertions and extend repeat runs. For macOS, first use a provisioned loader/capability harness to measure x18, 4 KB, low-address and per-thread TSO behavior (0A). Separately install the release-signed environment on an unrelated stock Mac with no recipient developer enrollment or machine registration (0B). Build pinned ARM64 Wine components in parallel; after 0A, launch an ARM64 Wine builtin, then integrate the already-tested FEX path. No accelerated graphics, launcher or AI is required. The unprovisioned macOS variants still fail with error 88; provisioning remains untested. [Linux experiment](experiments/linux-arm64-reference/README.md), [capability procedure](experiments/README.md).
6. **Reuse:** Wine PE loading/Win32/COM/MSI/GDI/macdrv/wineserver/tests; FEX decoder/IR/JIT/PE transitions and tests; Hangover build contracts; DXMT shader translation/cache/resource logic after CPU proof; UTM for optional VM use. Preserve separately replaceable components and license/source manifests. [01](01-landscape.md), [03](03-fex-hangover.md), [04](04-graphics.md), [06](06-licensing-security.md).
7. **First release:** a technical preview for an explicitly tested list of ordinary user-mode **x64 Win32 desktop** applications on validated macOS26.5+ builds, with isolated prefixes, reproducible versions, native windowing, text/input/clipboard/file access and actionable failures. Limit MSI to tested packages; bootstrapper custom actions are separate compatibility tests. Native Windows ARM64 is a useful control/secondary capability. Add selected DXMT D3D10/11 apps only after qualification. No universal installer, kernel-driver, anti-cheat, UWP, modern .NET/WPF/WebView2 or D3D12 promise. These exclusions define planned scope, not claims that all such software can never work. [03](03-fex-hangover.md), [04](04-graphics.md).
8. **Meaningful advantage over free solutions:** independently reproducible native execution plus evidence-backed version selection, safe reversible recipes and desktop regression testing. Measure successful workflows and fewer manual interventions against existing free packaging solutions. Do not market a speed advantage before matched benchmarks. [01](01-landscape.md), [09](09-roadmap.md).
9. **Five priorities:** (i) explain the Linux FEX prefix anomaly and reach 10 fresh-prefix passes; (ii) pursue Gate0A through free Apple inquiry routes while membership is unavailable; (iii) keep pinned public Wine components and the minimal Darwin loader build reproducible; (iv) assess Gate0B distribution separately and defer paid signing until there is a real authorization test; (v) after 0A, integrate FEX on Darwin and validate ABI/memory/thread correctness. Graphics and shell polish follow. [09](09-roadmap.md), [build experiment](experiments/native-wine-build/README.md), [Linux experiment](experiments/linux-arm64-reference/README.md).
10. **Invest:** yes in that bounded investigation. Do not hire/build a broad runtime team or design a polished GUI before the two gates pass. If Apple authorization is unavailable, reject Architecture A for the stated consumer product and assess Architecture D or release the evidence/diagnostic subsystem alone. If CPU integration needs a permanently large platform fork without maintainers, narrow or stop rather than promising universal support. [ADR](08-architecture-decision.md).

## Confidence and falsification

- **High documentary confidence:** APIs/source/build configurations/licenses cited with pins or local hashes.
- **Moderate execution confidence:** one local Linux reference test proves a narrow native ARM64 and x64 console path, while maintainer previews and developer reports provide additional evidence. The Linux prefix anomaly and all native macOS runtime behavior remain unresolved.
- **Low distribution confidence:** no successful third-party release provisioning/install test and contradictory free-account reports.
- **Unknown performance:** no matched application benchmark; native API implementation can reduce emulation work structurally, but does not prove speed, energy or latency improvements.

**GO conversion requires** a reproducible public stack, successful unrelated-stock-Mac installation without recipient enrollment/security weakening, repeated correct x64 and GUI execution, a credible small patch-maintenance plan and licenses satisfied. **NO-GO triggers for A:** capability unavailable to independent distribution; necessary integration remains inaccessible; or correctness/maintenance burden exceeds an explicitly funded small-team scope. Absence of evidence today is grounds for a prototype, not an assertion of impossibility.
